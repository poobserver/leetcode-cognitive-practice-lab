# 交付前验证

## 算法与内容

先运行参考解法及轨迹生成器。正常、未命中/不成立、最小输入、重复值或缺失位置等案例按题目约束选择；将结果与官方示例和适用的穷举/独立解法比较。核对复杂度是否包含输出与递归栈。迁移题同样核对。

生成器会检查 JSON 结构、案例引用、题目框架、问题答案、手填槽位、图节点和边等约束；它不证明算法正确。保存用于产生 frames 的代码，使每个演示状态可复算。

修改模板或构建器时可运行 `python scripts/test_builder.py`：检查真实轨迹与独立参考解法的结果、禁止把答案当编辑器初始值、图中边和节点的有效性、JSON 安全内嵌及真实返回链接。

## 浏览器

用可用浏览器工具查看实际产物。`scripts/verify_lesson.cjs` 使用 Playwright 做这些回归检查：

- 所有脚本可解析，页面无运行异常；六个模块及迁移入口可逆序直接进入。
- 所有案例逐帧可切换，前进/后退正确；普通答题选项不打开参考弹窗。
- 槽位初始空白，错误答案可重试；查看参考不改写槽位。
- 独立草稿在当前页面切换与复习后保留，重新载入清空；参考对话框打开时编辑器不可见。
- 页面不读写持久/会话存储；首页链接存在或使用概览返回入口。
- 390px 和 1440px 页面无整体横向溢出。

还要人工查看至少一份桌面图和手机图，以及树/链表/矩阵等本题核心可视化。自动校验无法证明箭头语义与教学设计正确。若浏览器工具不可用，完成可做的静态与算法检查，并如实说明界面交互尚未验证。

## 常见回退

输入法、引号与 `<` 可破坏手写内嵌脚本。使用构建器的 JSON 转义与文本 DOM，不用 `innerHTML` 插入未经转义的题面、用户代码或节点值。生成文件路径变化时重新检查本地返回链接。

不要为使测试通过而预填答案、写完成标志或跳过真实点击。修复底层按钮动作或导航逻辑后再复测对应行为。
